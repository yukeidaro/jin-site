// the real problem

Search isn't slow. You just can't choose between the results.

A 2008 longitudinal study settled this (Bergman et al., ACM TOIS). Swap in a better search engine, watch people for months, and they still reach files by navigating 56–68% of the time and searching only 4–15% — and making search better barely moved that number. Search is what people do when everything else has already failed.

$ everything DESIGN.md55 results in 0.02s
Speed was never the problem. Picking one of these 55 is.

208 files named README. 55 named DESIGN. 33 named lessons. Strip out every boilerplate file a framework generates and 1 in 5 still can't be told apart by name. And since you didn't write them, you don't know the words to search for in the first place.

// three axes

Give it a cover. Fold it down. Keep it traceable.

This is what people have done with books and shelves for centuries. Jin does it automatically, continuously, on a folder you already own.

01

Covermake it recognisable

Every document gets a cover you can identify at a glance. The first pass is generated without reading the file — name, type, date, location — so it appears instantly. The read-through pass swaps in quietly afterwards.

Constraint: the swap must not move row order or height
02

Foldcollapse the pile

2,650 items are never shown as 2,650 items. They fold into 9 labelled groups. Colour alone only says "these belong together", never what they are — so the group name is always spelled out in words.

Gate: 9 of 10 people answer correctly in a 5-second test
03

Tracesurvive the rewrite

Every paragraph, slide and cell range carries a stable ID. When an AI rewrites the document you can still see exactly what changed — at the level of meaning, not a file-level diff.

Gate: 99% ID survival across a round trip
$ jin fold ~/Documents  ·  2,650 files
// the gate

From install to the first "there it is" — 60 seconds.

Five minutes is a number your operating system's search already beats. It looks like a bar but it decides nothing. 60 seconds forces the design. Here is the budget, and what each line rules out.

30s
Launch, and pick one folder
→ rules out account creation, sign-in, onboarding, settings screens
10s
From folder picked to list on screen
→ rules out a loading spinner. Results stream in from the first row
20s
From list on screen to finding the one
→ 20s is scanning 10 things with your eyes. It is not reading 100
// what leaves your machine

What accumulates is not files. It's the rules.

v1 makes no network calls. One person installs it and their own machine gets cleaner and more legible — that alone is the whole value, so no rollout and no approval is required. Turn sync on later and the default is still that only the rules you authored leave the machine.

// non-goals

What Jin is not.

Written before what it is. Products that leave this vague try to become everything and end up as nothing.

Non-goalWhy
NOT 01Not a search engineEverything and Spotlight are free and genuinely fast. We don't compete there. Jin is for the case where you don't know the words.
NOT 02Not cloud storageIt doesn't replace OneDrive, Drive or Box. v1 never touches the network — it works on the disk you already have.
NOT 03Not another notes appIt adds no new place to write. It reads the 2,650 files already sitting on your disk. No migration, no import.
NOT 04Not a chatbotIt won't hand you a summary and call it done. The goal is that you see the whole shape yourself and choose for yourself.
