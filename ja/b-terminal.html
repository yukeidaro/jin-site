// the real problem

検索が遅いのではありません。
速く出てきても、選べないのです。

2008年の実証研究（Bergman et al., ACM TOIS）が既に答えを出しています。検索エンジンを良いものに入れ替えて長期観察しても、 人がファイルに辿り着く手段は たどる 56〜68% / 検索 4〜15%。しかも検索を良くしても使用率はほとんど上がりませんでした。 検索は、他が全部ダメだったときの最後の手段です。

$ everything DESIGN.md55 results in 0.02s
速さは問題ではありません。この 55 件から 1 件を選べないことが問題です。

README は 208 本、DESIGN は 55 本、lessons は 33 本。 定型ファイルを除いても 5 本に 1 本はファイル名だけでは特定できません。 そして、あなたはその文書を書いていないので、そもそも検索する言葉を知りません。

// three axes

表紙をつけ、畳み、たどれるようにする。

本を本棚に並べるときに人類が何百年もやってきたことを、自動でやります。

01

Cover表紙をつける

すべての文書に、見ただけで中身が分かる表紙を生成します。一段目は中身を読まずに即座に。読み込んだ二段目はあとから静かに差し替わります。

差し替え時に並び順・行高を動かさない
02

Fold畳む

2,650 本をそのまま見せません。区分ラベルで畳んで 9 区分にします。色だけでは「同じグループだ」としか伝わらないので、区分名の文字を必ず併記します。

5秒テスト: 10人中9人が答えられること
03

Traceたどる

段落・スライド・セル範囲に消えない ID を付けます。AI が書き換えても、どこがどう変わったかを意味の単位で追跡できます。

技術ゲート: ID 生存率 99%
$ jin fold ~/Documents/02\ Claude  ·  2,650 files
// the gate

インストールから最初の「あった」まで、60 秒。

5 分なら、いまの OS の検索でも達成できてしまいます。合格ラインに見えて、何も決めていない数字です。 60 秒にすると、作り方の選択肢が強制的に絞られます。それがこの数字の目的です。

30s
起動して、フォルダを 1 つ選ぶまで
→ アカウント作成・ログイン・チュートリアル・設定画面を置けない
10s
選んでから、一覧が出るまで
→「読み込み中…」で待たせられない。先頭から画面へ流し込むしかない
20s
一覧が出てから、目的の 1 件を見つけるまで
→ 20秒は「10件を目でなぞる」時間。「100件を読む」時間ではない
// what leaves your machine

貯まるのはファイルではなく、整理の規則です。

v1 はネットワークに出ません。一人が入れて、自分の PC の中が綺麗になっていく。それだけで価値が完結します。 会社の承認は要りません。同期を有効にしても、既定で上がるのはあなたが作った規則だけです。

// non-goals

Jin でないもの。

何であるかより、何でないかを先に書きます。ここを曖昧にした製品は、全部になろうとして何にもなりません。

非目標理由
NOT 01検索エンジンではないEverything も OS 検索も無料で、しかも速い。そこでは戦いません。Jin は「探す言葉を知らない人」の道具です。
NOT 02クラウドストレージではないOneDrive も Box も置き換えません。v1 はネットワークに出ず、あなたのディスクの上で完結します。
NOT 03もう一つのメモアプリではない書く場所を増やしません。すでにディスクにある 2,650 本を読むだけ。移行もインポートもありません。
NOT 04チャットボットではない要約を読ませて終わりにしません。あなたが自分の目で全体像を掴み、自分で選べる状態にすることが目的です。
