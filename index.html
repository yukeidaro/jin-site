What both pages say, in order
  1. The problem: Markdown file chaos — every agent files by its own logic, and half of what lands was never meant for you
  2. The method: two structures kept in sync — your decisions get written back into CLAUDE.md, AGENTS.md and the rest, so the next file lands where you'd have put it
  3. The product: one workspace, three views, plus a visual Markdown editor
  4. How we ship: free and open source for individuals, paid for organisations
  5. Team: Yu Asano and Tomoya Kato
  6. Upcoming, then the waitlist
The waitlist needs one line to go live Both pages ship with a working form. Until an endpoint is set it falls back to opening the visitor's mail client, so it is never a dead button. To make it collect properly, open either page and set the two constants near the bottom of the file:
WAITLIST_ENDPOINT — a Formspree, Tally or Basin URL that accepts a POST with an email field
WAITLIST_EMAIL — the address the mail fallback writes to
